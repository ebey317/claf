# Contributing

Thanks for your interest in contributing. I (the sole maintainer) ask that you read this guide before opening an issue or PR.

## Issues

- **Search first.** Check existing issues (open + closed) before opening a new one.
- **One issue, one topic.** Keep bug reports, feature requests, and questions
  separate.
- **Repros help.** For bugs, include: OS, version/commit, exact steps, expected
  vs actual behavior, logs / screenshots.
- **Be patient.** I work on this in my spare time; replies may take a few days.

## Pull Requests

1. **Open an issue first** for non-trivial changes so we can discuss direction.
2. **Fork and branch off `main` (or `master` — see README).**
3. **Match existing style.** Read a few files first. Don't reformat code that
   isn't related to your change.
4. **Test what you can.** If the repo has tests, run them. If it doesn't, say so
   in the PR.
5. **One logical change per PR.** Split unrelated changes into separate PRs.
6. **Write a clear PR description:** what, why, how to test, screenshots if
   visual.

## Development setup

Check the README for install/run instructions. Other repositories in this profile follow
the same general pattern; if you get stuck, file an issue.

## Security

Report security issues privately — see `SECURITY.md`. Do not file a public
issue.

## Code of Conduct

By participating, you agree to abide by the `CODE_OF_CONDUCT.md`.
